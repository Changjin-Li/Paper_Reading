MomADv2: Reliable Temporal Memory for End to End Autonomous Driving

MomADv2: Reliable Temporal Memory for End-to-End Autonomous Driving

arXiv Preprint·Yanshan University, Beijing Jiaotong University, Nanyang Technological University, Tsinghua University, China Automotive Technology and Research Center, Beijing Institute of Technology, University of Macau, The University of Queensland·Ziying Song , Shengkai Zhang, Lin Liu, Peiliang Wu, Lei Yang, Dongyang Xu, Bin Sun, Li Wang, Shaoqing Xu, Caiyan Jia, Yadan Luo

Nov 26, 2026

  • imitation-learning

Summary

MomAD 把上一帧的 planning query 无条件传给当前帧，这在场景突变、时序断裂或导航命令切换时会把无效意图带进来。MomADv2 把”是否复用历史”做成一个显式的可靠性判定：维护一个以（命令，时序连续性 token）为键的记忆库，只保留命令一致、时序连续且非空的条目；再用按时间偏移对齐的轨迹距离在每个候选上找到历史对应项，按相似度与时间衰减加权，最后用一个可靠性门控把 SSM 输出的残差裁剪后注入当前 query。轨迹侧另加 Flow-Matching Trajectory Residual Refiner（FM-Ref）：把 planner 输出当作流匹配的起点、专家轨迹当作终点，学一个条件残差速度场，推理只需 2 步 Euler，且用有界门控保证只做修正、不替换 anchor-based planner 的输出。nuScenes 6 s 时域下平均碰撞率从 MomAD 的 0.90% 降到 0.76%（−15.6%）、平均 L2 1.21 m；Bench2Drive 闭环 SR 从 18.11% 提到 24.24%；NAVSIM v1 PDMS 89.9、v2 navtest EPDMS 87.9、navhard 39.5。

Problem & Motivation

  • 长时域规划要求跨帧的规划状态一致，因此 temporal memory 是必需品；MomAD 证明了用历史 planning query 做 momentum 能降低模式不稳定与轨迹抖动。
  • 但历史并不总是可靠：动态场景变化、时序不连续（丢帧、跳 scene）、以及高层导航命令切换时，历史意图与当前意图不一致，直接复用会产生负迁移。
  • 现有做法要么整段复用历史 query，要么只做时序特征建模，缺少”这条历史还该不该用”的判定；这是论文主张的核心缺口。
  • 另一个问题是误差累积：anchor-based planner 的候选来自离散 anchor 附近的偏移，长时域上会累积局部偏差，而扩散式生成器虽然能细化，却会破坏 anchor planner 的稳定性。
  • 因此需要两个机制：可靠的历史筛选（决定读什么）与受约束的残差细化（决定改多少）。

Method

0. 总体框架

  • 感知与规划沿用稀疏范式：多视角图像 → 稀疏 scene representation → anchor-based 运动/规划解码器，输出多模态运动预测与初始 ego 候选。
  • 在其上接两个模块：SSM-Q 负责筛选并增强历史 planning query，FM-Ref 负责在候选轨迹上做残差修正；前者读记忆，后者不读记忆。
  • 训练分两阶段：Stage I 按 MomAD 原配方训出完整模型；Stage II 冻结 backbone、感知、运动预测与大部分规划头，只训新增的 SSM 编码器、门控、残差头与流匹配头（10 epoch，lr 3×10−6，8×RTX 4090）。

1. 记忆库的构造与写入策略（附录 A.5）

  • 记忆条目以（命令，时序连续性 token）为复合键，值存增强前的原始 query 与 baseline 候选轨迹：
Mt​={χt−k​↦(Qt−kraw​, Yt−kbase,cmd​, ct−k​)}k=1K​
  • ct−k​∈{left,straight,right} 是高层命令，χt−k​ 是帧级连续性标识（只用做索引与硬掩码，不作为特征输入）。
  • 关键设计是read-before-write：每帧先读历史、出结果，再把本帧的原始 query 与 baseline 轨迹写入；SSM 增强后的 query 与 flow 修正后的轨迹都不回写。这避免了”修正被反复叠加”的自激漂移。
  • 记忆是 FIFO，容量 K=4；每个 sequence 开始、跨 scene、无有效前驱或帧间隔异常时整体重置。

2. 可靠历史检索（§3.2）

  • 三类有效性同时满足才允许使用：命令一致、时序连续、历史 query 非空：
mt,k​=I[ct​=ct−k​, χt(−k)​=χt−k​, Qt−kraw​=0]
  • 命令过滤是硬约束：当前是左转时，只允许检索历史帧中的左转候选，直行/右转候选完全不可见。
  • 同一命令下的候选顺序会随场景变化而漂移，因此不能按固定索引对齐；对每个当前候选 j，在该命令的历史候选里找轨迹最一致的一条：
ht,k,j∗​=argh∈{1,…,Mc​}min​Dshift​(Yt−k,hbase,cmd​, Yt,jbase,cmd​)
  • Dshift​ 是带时间偏移的轨迹距离：历史轨迹预测的起点早 k 帧，先丢掉已经流逝的 sk​=round(kΔframe​/Δtraj​) 个 waypoint，再把剩余点变换到当前 ego 坐标系，只在重叠时域上算平均距离；非整数偏移用线性插值。没有这一步，“同一意图”会被误判为不一致。
  • 对应的历史 query 按全局索引取出：Q​t,k,jhist​=Qt−kraw​[idx(ct​,h∗)]。

3. 可靠性加权的时序聚合（§3.2）

  • 历史 query 按有效性、轨迹相似度与时间衰减加权求和：
Qˉ​t,jhist​=k=1∑K​wt,k,j​Q​t,k,jhist​,wt,k,j​=∑k′​ϕt,k′,j​+ϵϕt,k,j​​ ϕt,k,j​=mt,k​exp(−αdt,k,j​​)exp(−βk​)
  • dt,k,j​ 是对齐后的轨迹距离，α 控制”轨迹差多少就不信”，β 控制”多旧就不信”；两个指数项分别对应空间与时间两个维度的衰减。
  • 另有一个可靠性门控，防止”只有一条历史有效”时被单条噪声主导：
rt,j​=rtcnt​⋅rt,jdist​,rtcnt​=min(K0​∑k​mt,k​​,1),rt,jdist​=σ(γd​d0​−mink​dt,k,j​​)
  • rcnt 要求有效历史条数达到 K0​ 才给满权重，rdist 在最近邻轨迹距离小于阈值 d0​ 时才打开；两者相乘意味着”历史够多且至少有一条足够像”才会真正影响当前规划。

4. Selective SSM 编码与残差注入（§3.2）

  • 把对齐后的历史 query 按时间从远到近与当前 query 拼成序列，送 selective state-space 编码器（LN → causal depthwise conv → 输入相关的 selective scan → SiLU 门控 → 残差），取最后一个 token 作为当前意图：
Zt,j0​=Concat(Q​t,K,jhist​,…,Q​t,1,jhist​,Qt,j​),Ht,jcur​=SSMEncoder(Zt,j0​)[−1]
  • 注入方式是残差而非替换，并做范数裁剪：
ΔQt,j​=tanh(Ht,jcur​−Qt,j​),Ut,j​=Clip(gt,j​ΔQt,j​, ρ∥Qt,j​∥2​),Q​t,j​=Qt,j​+Ut,j​
  • gt,j​ 汇总有效历史指示、全局残差门、可靠性门、候选级门与残差尺度；ρ 限制单次扰动幅度。这样即使检索到错误历史，最坏情况也只是有限的 query 偏移。

5. Flow-Matching 轨迹残差修正（§3.3）

  • 与从噪声生成轨迹的扩散/流匹配不同，这里把 planner 精炼后的轨迹当起点、专家轨迹当终点，学一个条件残差速度场。先把位移式轨迹累加成绝对轨迹并归一化：
Ytref​=Cumsum(Ytref​),x0​=sYtref​​,x1​=sCumsum(Yt⋆​)​
  • 在两端之间做线性插值，目标速度就是残差位移：
xτ​=(1−τ)x0​+τx1​,v⋆=x1​−x0​,LFM​=​fθ​(Q​t​,xτ​,τ)−v⋆​22​
  • 速度场以增强 query、当前轨迹状态与流时间为条件，先各自投影拼接、过 MLP + LayerNorm + Transformer encoder，再由 MLP 头输出；planner 侧输入做 stop-gradient，避免辅助目标扰动主规划器。
  • 推理从 x0​ 出发做 S=2 步 Euler 积分，再用有界门控控制修正强度：
xk+1​=xk​+S1​fθ​(Q​t​,xk​,τk​),η=ηmin​+ηmax​σ(gflow​) Ytflow​=s[x0​+η(xS​−x0​)]
  • η 的上界保证输出不会离 planner 候选太远——这是”保留 anchor-based 稳定性”的具体实现；最后再用差分把绝对轨迹转回位移式。
  • 总损失：
L=Lplan​+LSSM​+λflow​Lflow​+λFM​LFM​,Lflow​=λΔ​ℓreg​(Ytflow​,Yt⋆​)+λcum​ℓreg​(Ytflow​,Yt⋆​)
  • 位移式与累积式两套监督同时使用，前者约束逐点位置、后者约束整体形状。

Pipeline

多视角图像编码为检测与地图表示，anchor-based 解码器产出初始 planning query 与命令相关的候选轨迹；SSM-Q 依据命令、时序连续性、轨迹相似度与 buffer 状态筛出可靠历史，按时间顺序送 selective SSM 编码并以有界残差注入当前 query；FM-Ref 再把精炼后的轨迹当作流匹配起点，学一个指向专家轨迹的残差速度场，经 2 步 Euler 与有界门控输出最终轨迹。

  1. 感知与初始规划：稀疏 scene representation → anchor-based 头输出多模态运动预测与按命令分组的 ego 候选。
  2. 读记忆：取最近 K=4 帧条目，按”命令一致 + 时序连续 + query 非空”做硬过滤。
  3. 轨迹对齐检索：对每个当前候选，丢弃已流逝 waypoint、变换坐标系后算 Dshift​，找历史最一致的一条并取出其原始 query。
  4. 加权聚合：按相似度与时间衰减算权重，再乘上”有效条数”与”最近邻距离”两个可靠性门。
  5. SSM 编码与注入：历史 + 当前 query 组成短序列，经 selective SSM 取末位状态，残差经 tanh 与范数裁剪后加回当前 query。
  6. 规划精炼：增强 query 送规划头，输出分类、轨迹回归与规划状态。
  7. 残差细化：轨迹累加成绝对形式并归一化，从 x0​ 出发做 2 步 Euler，得到 xS​ 后按有界 η 与原轨迹混合，再转回位移式作为最终输出。
  8. 写回：只把本帧的原始 query 与 baseline 轨迹写入记忆，增强/修正结果不写回。

Strengths & Weaknesses

Strengths

  • 问题选得准：把”历史什么时候不可信”拆成可实现的三个判据（命令一致、时序连续、轨迹相似），而不是笼统地说”要做选择性记忆”。
  • 朴素融合 1.01 差于无记忆 0.92 这一行是全文最强证据：它直接证明”无条件复用历史会负迁移”，也让后续每一层过滤的增益有了参照。
  • 时间偏移对齐处理得细：丢掉已流逝 waypoint、变换 ego 坐标系、非整数偏移做插值，避免了”同一意图因时间原点不同被误判为不一致”这个常见坑。
  • 门控体系完整且各有明确失效模式：有效条数门管”历史不够”，距离门管”没有一条像”，范数裁剪管”即使检索错也只偏移有限量”。
  • FM-Ref 的定位清楚：不是从噪声生成轨迹，而是从 planner 输出做残差运输；有界门控 η 保证输出不会离开 anchor 候选太远，这个”只修正、不替换”的设计对工程部署友好。
  • 选型有代价证据：Selective SSM 比 Transformer 高 0.7 EPDMS、快 30%；Euler 优于 Heun。这两组对比让架构与求解器的选择不是凭直觉。
  • 做了三套 benchmark（nuScenes 开环、Bench2Drive 闭环、NAVSIM 伪闭环），比只报单一指标更完整。

Weaknesses

  • “long-horizon”与技术机制不匹配：K=4 最好、K=6/8 退化，记忆实际覆盖约 2 s 的 planning state；论文标题与动机都指向长时域，但没有解释为什么更长的历史反而有害，也没有做逐帧贡献分析。
  • 增益集中在很小的绝对量：nuScenes 平均碰撞率 0.90 → 0.76 个百分点，Table 7 各档之间只差 0.03–0.06；全文无 seed、无标准差、无置信区间，这些差异是否超出训练噪声无法判断。
  • 依赖预定义命令：记忆检索以 ct​∈{left,straight,right} 为硬键，命令本身错了（或没有导航输入）时，整条检索链路失效；作者在 limitation 里承认，但这是方法可用性的核心前提。
  • FM-Ref 的归因不清：消融只做了”有无 FM-Ref”，没有”同等参数的残差 MLP 但不做 flow”的对照；因此 3.0 PDMS 的增益无法区分”flow 参数化的好处”与”多一个细化头的好处”。
  • Table 7 的所有变体都带 FM-Ref：记忆策略的比较是在同一个强细化头上做的，若换成不带 FM-Ref 的配置，过滤各层的相对重要性可能不同。
  • Bench2Drive 的 78.82 与 24.24 是两个不同配方：带专家特征蒸馏的版本 DS/SR 高得多，但 Comfort 只有 31.23，与不带蒸馏版本的 55.11 差距巨大；论文把它们放在同一张表里，容易被读成同一方法的两个数字。
  • 跨 benchmark 的 backbone 不一致：nuScenes 用 ResNet-50、NAVSIM 沿用 TransFuser 的 ResNet-34，三套协议的数字不可横向比较；“NAVSIM v1 89.9 并列最高”只在表内成立，同期 PlanWAM 报 93.8、RiSE 报 94.2。
  • 推理开销只给了相对 FPS：Table 13 是记忆模块的吞吐（43.0 vs 51.0 FPS），但没有给完整模型（含 FM-Ref 的 2 步 Euler）相对 MomAD 的延迟与显存；对一个”实时规划”方法，这是关键缺失。
  • 记忆库不跨 scene：跨 scene 即重置，因此方法只处理短期状态惯性，无法利用”同一路段的历史经验”；这与外部场景记忆（街景先验、失败案例库）是两条不同的线，论文没有讨论二者关系。
  • 失败模式未统计：作者提到 baseline 候选不准时对齐会失效，但没有给出”检索被全部拒绝”的比例，也没有按场景类型拆解闭环失败。

Notes

  • 论文定位：不是新的感知或生成架构，而是把 MomAD 的”单步 planning-state 记忆”升级成带可靠性判定的短期记忆。它属于 memory 在规划里最轻的一档：不建外部库、不做语义检索，只在最近 4 帧的 planning query 上做筛选与状态空间演化。

  • 可迁移点：

    • “先判断该不该用，再决定怎么融合” 是比”设计更强的融合模块”更根本的一步；Table 7 里朴素融合差于无记忆，说明任何 memory 模块都应当先做有效性过滤。
    • 时间偏移对齐是跨帧轨迹比较的必要预处理：丢掉已流逝 waypoint、变换坐标系、非整数偏移插值，这套操作可以直接复用到任何”跨帧候选一致性”或”跨帧损失”里。
    • 有效条数门 + 距离门 + 范数裁剪三层保护可以套到任何”外部信号注入主干”的模块上：条数门防单条噪声主导，距离门防语义不符，裁剪防最坏情况失控。
    • 有界残差细化（flow 学残差、η 限幅、只修正不替换）是一个适合工程部署的折中：既拿到生成式细化的收益，又不破坏 anchor planner 的稳定性。
    • Selective SSM 用于短序列（K≤4）在精度与吞吐上都优于 Transformer（87.9 vs 87.2 EPDMS、43.0 vs 33.0 FPS），这个结论对”短历史 + 实时”的场景有直接参考价值。

  • 待跟进：

    • 为什么 K>4 会退化：是旧 query 的语义漂移、还是可靠性门在长窗口下误判？需要逐帧贡献分析（分别只用第 1/2/3/4 帧历史）。
    • 命令错误的鲁棒性：给命令注入随机翻转，统计记忆检索被拒绝的比例与碰撞率变化，判断方法对导航输入的依赖强度。
    • FM-Ref 的归因：加一组”同参数量的残差 MLP（无 flow、无 Euler）“对照，把”生成式参数化”的净收益从”多一个细化头”里剥离出来。
    • 完整推理开销：报出含 SSM-Q + 2 步 Euler 的端到端延迟、显存与吞吐，而不只是记忆模块的 FPS。
    • 与外部记忆的结合：短期 planning-state 记忆（本文）与长期场景记忆（街景先验、失败案例检索）能否叠在同一条规划管线里，目前没有工作验证。
    • 闭环失败拆解：按 cut-in、无保护左转、环岛等场景统计 SR，看”可靠记忆”在哪些交互下反而保守过度。
