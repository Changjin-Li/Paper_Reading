Latent WAM++: Shaping World and Action Representations for End to End Autonomous Driving

Latent-WAM++: Shaping World and Action Representations for End-to-End Autonomous Driving

arXiv Preprint·Institute of Automation, Chinese Academy of Sciences, Chongqing Changan Technology Co., Ltd.·Yichen Zhang , Yupeng Zheng, Linbo Wang, Pengxuan Yang, Zebin Xing, Junli Wang, Shiwei Li, Kangwei Liu, Fan Ren, Qichao Zhang, Yifeng Pan, Ji Tao, Dongbin Zhao

Nov 17, 2026

  • world-model
  • flow-matching

Summary

现有 WAM 大多只监督”预测的未来状态”或”最终动作”，夹在中间的 world representation 与 action representation 只被这些输出目标间接约束。Latent-WAM++ 的主张是给每种表示的监督匹配它在规划中的角色：WoRC 用 scene-ego 未来潜预测 + SIGReg 分布正则 + 冻结几何先验，得到”可预测、不塌缩、带几何”的世界表示（并去掉 EMA target encoder）；TrajMF 直接预测干净轨迹、但在 Improved MeanFlow 的诱导速度空间施加监督，一步采样出 Kp​ 条多模态 proposal；VARA 把这些 proposal 的 pre-output 特征与 stop-gradient 的当前视觉语义做非对称 cosine 对齐。NAVSIM v2 90.1 EPDMS，HUGSIM 零样本 47.0 RC / 30.1 HD-Score，端到端训练 planner 190 GPU-hours，对 Latent-WAM 的 1,600 降低 88.1%。

Problem & Motivation

  • WAM 的信息通路可以写成三段：观测 → world representation（哪些场景信息可用）→ action representation（如何翻译成轨迹）→ 轨迹。因此规划性能同时取决于两个表示本身以及它们的交互方式。
  • 早期工作只监督预测的未来状态或最终动作，中间表示是输出导向目标的副产物，没有被直接塑形。
  • 第一个缺陷：联合训练 encoder 与 latent predictor 时没有 anti-collapse 机制，模型可以靠把所有场景映射到相近 token 来降低预测损失（low-variance 解），表示虽然”可预测”但没有区分度。Drive-JEPA / Latent-WAM 用 EMA target encoder 来挡，代价是多一份目标编码器。
  • 第二个缺陷：world conditioning 只让 action decoder “看得到”场景信息，没有在表示层面施加对齐。两个表示空间可以任意漂移，无法保证 action representation 保留了 world model 编码的规划相关信息。
  • 由此把问题统一为：world 表示应当可预测、非退化、几何感知；action 表示应当直接参数化轨迹；二者的对应关系要被显式鼓励，但不强求共享同一语义（这是 VARA 采用非对称 cosine 而非逐元素对齐的原因）。

Method

0. 总体框架

  • 三个组件各管一段：WoRC 造世界表示 Wtcur​​ → TrajMF 以 W 为条件生成并聚合轨迹，其 pre-output 特征 Ha​ 定义 action representation → VARA 在 Ha​ 与当前视觉 token 之间加一条表示级正则。
  • 训练时额外接两个只在训练期存在的分支：动态世界模型 DWM（预测未来潜 + ego 状态）与冻结几何 teacher（patch 级蒸馏）、冻结 occupancy 提取器（当前帧几何上下文）。
  • 推理只用模态编码器与 TrajMF，输入仅为相机图像与 ego 状态。

1. WoRC：世界表示构造（§3.2）

  • 场景编码：每个视角、每一帧广播 Nq​ 个可学习 query，与 patch token 拼接后过 DINOv2 编码器与 projector：
[Fv​,X]=Pv​(Ev​([Qv​;X])),Fv​∈RT×Nv​×D, Nv​=VNq​
  • 其中 X 是投影后的 patch 特征，专门留给几何蒸馏用；默认 3 个视角 × 16 query = 48 个视觉 token，D=256。
  • 几何蒸馏：DINOv2 特征缺少度量空间线索，所以用冻结的 WorldMirror teacher 在 patch 层面做 stop-gradient 的余弦蒸馏：
Lgeo​=1−cos(LN(Pg​(X)), sg(LN(Egeo​(I))))
  • 这里 Pg​ 把视觉 patch 特征投到 teacher 的特征空间；蒸馏只训练 Pg​ 与视觉侧，teacher 分支不产生可训练参数。
  • ego 与 occupancy 线索：ego 状态经编码器得到 Fe​=Ee​(Sego​)；当前帧由冻结 occupancy 提取器给出占据栅格，栅格单元经 MLP 投成 token，再由视觉 token 做 cross-attention 取用：
Focctcur​​=Aocc​(Fvtcur​​,Otcur​​,Otcur​​)
  • planning 时的世界表示是三者拼接，且只有当前帧进入 planner：
Wtcur​​=[Fetcur​​;Fvtcur​​;Focctcur​​]∈R(1+2Nv​)×D
  • ego token 提供导航意图与运动学、视觉 token 提供语义、occupancy token 通过 query 选择提供度量几何——三种信息在同一序列里以不同来源区分。
  • 时间潜预测（DWM）：把 Zt​=[Fet​;Fvt​] 送进带 3D rotary positional encoding 的 Transformer decoder，位置编码覆盖时间、相机视角与 query identity，掩码允许帧内双向、跨帧因果（frame-wise teacher forcing）：
Z2:T​=Ddwm​(Z1:T−1​),Lwm​=MSE(Z2:T​,Z2:T​)
  • ego 侧另加命令分类与速度/加速度回归：Lego​=Lcmdce​+MSE(v^,v)+MSE(a^,a)，合起来 Ldwm​=Lwm​+Lego​。
  • 分布稳定化（SIGReg）：对每个 token identity n，跨 batch 估计经验特征函数，并与标准高斯匹配：
φ​tnj​(ωℓ​)=B1​b=1∑B​exp(iωℓ​rj⊤​fb,t,n​),Lsigreg​=TNv​JB​t,n,j,ℓ∑​wℓ​​φ​tnj​(ωℓ​)−e−ωℓ2​/2​2
  • rj​ 是随机单位方向、ωℓ​ 是积分频率、wℓ​ 是积分权重。这个正则没有 target encoder：它约束的是”同一 token 在不同场景下的分布”，因此不需要额外的 EMA 网络就能避免低方差解。

2. TrajMF：轨迹 MeanFlow 规划器（§3.3）

  • 先把世界表示压成规划条件：Na​ 个可学习 action query 对 W 做 cross-attention 得 Ctcur​​，条件 c=(W,C)。
  • 把专家轨迹归一化成相对轨迹 x=R(τ)，噪声 ϵ 从 Kp​ 分量高斯混合先验 p 采样，线性流路径与目标速度为：
zt​=(1−t)x+tϵ,vt​=dtdzt​​=ϵ−x
  • 关键设计是”预测 x、监督 v“：网络直接输出干净轨迹 xθ​=Fθ​(zt​,r,t,c)，再换算成诱导平均速度：
uθ​=tzt​−xθ​​ (t>0),(vθ​,⋅)=JVP[uθ​(⋅∣c);(zt​,r,t);(vins​,0,1)]
  • JVP 沿诱导轨迹方向求方向导数，避免显式构造 Jacobian；瞬时速度用一阶展开构造，导数项 stop-gradient：
vθ​=uθ​+(t−r)sg(u˙θ​),Ltrajmf​=∥vθ​−vt​∥1​
  • 采样阶段不需要任何速度换算：从 p 的每个分量各取一个噪声，Fθ​({ϵk},0,1,c) 一次前向得到 Kp​ 条 proposal，再由 refiner Drefine​ 条件聚合为最终轨迹，Ltraj​=∥x−x∥1​。
  • action representation 的定义：每条 proposal 在输出头之前的特征 hak​ 被收集成 Ha​=[ha1​;…;haKp​​]∈RKp​×D。选它而不是最终轨迹，是因为它是”直接支撑轨迹预测”的最后一层表示，也是 VARA 要正则的接口。
  • 与 iMF 的差别只在预测目标：iMF 预测平均速度 u，TrajMF 预测轨迹 x，二者都在速度空间监督；论文的说法是在低维轨迹空间两者都能work，但预测 x 收敛更快（见 Key Results 的迭代数对比）。

3. VARA：视觉-动作表示对齐（§3.4）

  • 把 proposal 特征投影后平均，得到动作侧表示；视觉侧取当前帧 token 平均并 stop-gradient：
za​=Kp​1​k=1∑Kp​​Pa​(hak​),zv​=sg(Nv​1​n=1∑Nv​​Fvtcur​,n​),Lalign​=1−cos(za​,zv​)
  • 三个设计点：①用余弦而不是 MSE，只要求语义一致、不要求逐元素相等；②梯度只经动作侧回传，视觉侧被 sg 挡住，避免把视觉表示拉向动作表示（非对称正则）；③对齐的是”规划前的动作特征”而不是输出轨迹，等于给 decoder 内部加了一个语义锚。

4. 训练与推理（§3.5）

  • 损失按”世界 / 动作 / 对齐”分组：
Lworld​=λ1​(Lgeo​+Ldwm​+Lsigreg​),Laction​=λ2​Ltrajmf​+λ3​Ltraj​,L=Lworld​+Laction​+λ4​Lalign​
  • 权重 λ1​=0.2、λ2​=20.0、λ3​=7.0、λ4​=2.0；推理时只保留模态编码器与 TrajMF，几何 teacher、DWM、SIGReg、VARA 全部不参与。

5. 实现细节

项设置

几何分支冻结 WorldMirror-based teacher（仅训练期蒸馏）

Pipeline

WoRC 用 DINOv2 视觉 token、ego token、occupancy token 与冻结几何蒸馏构造世界表示，并由 DWM 做 scene-ego 未来潜预测、SIGReg 稳定分布；TrajMF 以世界表示为条件，一次前向从高斯混合先验生成多条轨迹 proposal 并聚合；VARA 把 proposal 的输出前特征与当前视觉语义做 stop-gradient 的余弦对齐。训练期的 DWM、几何 teacher 与 VARA 在推理时都不保留。

  1. 编码：3 路相机图像 + 可学习 query 过 DINOv2-B，得视觉 token Fv​；ego 状态编码为 Fe​；当前帧 occupancy 栅格经 MLP 成 token O。
  2. 世界表示：视觉 token cross-attend occupancy 得 Focc​，与 Fe​,Fv​ 拼成 Wtcur​​（只含当前帧）。
  3. 训练期世界监督：DWM 用因果掩码预测未来帧的 [Fe​;Fv​]；SIGReg 约束同一 token 跨场景分布；冻结几何 teacher 在 patch 级蒸馏。
  4. 条件化：Na​ 个 action query 对 W 做 cross-attention 得 C，与 W 一起构成条件 c。
  5. 一步生成：从 Kp​ 分量高斯混合先验各取一个噪声，Fθ​(⋅,0,1,c) 一次前向输出 Kp​ 条 proposal，收集 Ha​ 作为动作表示。
  6. 聚合与对齐：refiner 条件聚合 proposal 得最终轨迹；训练时 VARA 用 Ha​ 的均值与 stop-gradient 视觉均值算 cosine 对齐损失。
  7. 推理：只跑 1–2、4–6，DWM / SIGReg / 几何 teacher / VARA 全部移除；输出一条轨迹。

Strengths & Weaknesses

Strengths

  • “为每种表示匹配其规划角色”是一个可操作的框架，而不只是口号：world 表示对应”可预测 + 非退化 + 几何”，action 表示对应”直接参数化轨迹”，接口对应”非对称语义一致”。三个组件都能从这句话推出来。
  • SIGReg 替代 EMA 是干净的结构简化：省掉 86.6M 参数的目标编码器，性能仍从 88.6 提到 88.8；并且论文给了标准差 0.088→0.900、余弦相似度 0.973→0.017 这种可直接复核的量化证据，比”我们观察到表示更好”有力得多。
  • TrajMF 的”预测 x、监督 v“是一个值得记住的工程技巧：采样时不需要任何速度换算，一步出多模态 proposal；训练时又能享受 velocity-space 目标的稳定性。
  • 消融包含了负结果：ID 2 的 −0.2 明确写出”加世界模型但不加稳定化会更差”，这类信息比只报最优配置更有价值，也解释了为什么必须引入 SIGReg。
  • VARA 的非对称设计有明确理由：只用 stop-gradient 视觉目标、只回传动作侧，避免两个表示互相拉扯；用 cosine 而非 MSE 避免强迫逐元素对应，这与”不强求共享语义”的论点一致。
  • 成本主张有对照口径：明确写了”同硬件、同 data-loading”，并给出 GPU-hours 而非只给 epoch 数，比多数论文的”训练更快”更可核查。
  • 零样本闭环做了跨难度拆分：四档分别报 RC 与 HD-Score，读者能看到收益来自 Hard 档而不是平均掩盖。

Weaknesses

  • 增益幅度小、且叠加式消融无法隔离交互：90.1 对基座 89.3 只有 +0.8，对 MeanFuser 89.5 只有 +0.6；Table 3 是顺序累加的 8 行，每行只加一个组件，既没有单独移除某项的 leave-one-out，也没有 seed / 方差，0.2–0.4 的单步增益无法排除训练噪声。
  • “190 vs 1,600 GPU-hours”的口径没有拆开：两个模型的 backbone、训练 epoch、planner 结构与采样步数都不同。省下的算力究竟来自一步采样、更小的 DINOv2-Base、还是 25 epoch 的短训练，论文没有做”固定 backbone / 固定 epoch 只换采样步数”的对照，−88.1% 这个数字容易被读成”方法本身的效率”。
  • TrajMF 相对 iMF 的精度增益只有 0.1：真正的差异是迭代数减半，但没有 wall-clock、FLOPs 或每步耗时；在 batch 128、16 卡的设置下，迭代数受 lr schedule 与数据加载影响，不能直接换算成加速比。
  • HUGSIM 结果并非全面领先，但正文只讲平均值：Easy RC 80.1（Latent-WAM 84.2）、Extreme RC 32.0（35.5）、Extreme HD 13.9（18.1）都退步，论文没有讨论”为什么两端变差”。一个合理但未验证的猜测是 TrajMF 的混合先验在极端场景下覆盖不足，但缺少按场景类型的失败统计。
  • occupancy 分支的输入来源含糊：正文说”所有输入来自相机与 ego 状态，不需要额外传感器”，但 occupancy 提取器是冻结的，其训练依赖 NuPlan-Occ 的标注（附录 A.3），提取器本身的输入模态（图像 / LiDAR / 深度）没有交代。如果它隐式用到了 LiDAR 或标注深度，“仅相机”的宣称就打折扣，复现也无从下手。
  • VARA 的机制证据偏弱：+0.3 EPDMS 只配了一张聚类可视化；没有做”对齐到视觉 CLS / 对齐到 world 表示 / 双向对齐 / 换成 MSE”的对照，也没有探针说明动作特征到底继承了什么视觉语义（语义分类？几何？运动？）。
  • 超参缺乏敏感性：λ2​=20 与 λ3​=7 的量级差异、λ4​=2.0、SIGReg 的方向数 J 与频率网格都没有消融；考虑到各组件增益本身只有 0.2–0.4，超参选择对结论的影响可能不小于组件本身。
  • “SOTA” 的对照集合有时间窗问题：论文报 90.1 EPDMS 并称 state-of-the-art，但同期 PlanWAM（2610.11382）在同一 benchmark 上报 90.9 EPDMS，基座 Latent-WAM 的 89.3 也在其表内。baseline 集合没有覆盖这批工作，因此”SOTA”只对论文所选比较集成立。
  • 几何蒸馏的收益未与 occupancy 分离：Table 3 中 occupancy（+0.3）与几何蒸馏（+0.3）都是”加几何信息”，但一个是推理期可见的 token、一个是训练期蒸馏；两者是否在提供同一份信息、能否只留一个，论文没有做交叉消融。

Notes

  • 论文定位：不是新的 WAM 架构，而是对 WAM 中间表示的监督重新分工——world 侧负责”可预测、不塌缩、带几何”，action 侧负责”直接参数化轨迹”，接口侧负责”语义一致但不必同构”。核心 insight 是：中间表示的性能不是靠更大模型或更多输出监督堆出来的，而是靠”监督信号是否匹配该表示在规划中的用途”。
  • 可迁移点：
    • SIGReg 作为 EMA-free 的 anti-collapse 手段：任何”encoder + 未来预测器”联合训练的自监督世界模型都可以直接换上，代价是每个 token identity 上的一次跨 batch 特征函数估计，省掉一整份 target encoder。
    • 预测干净样本、在诱导速度空间监督：在低维动作空间里，这种组合可以既保留一步采样的便利，又获得 velocity-space 目标的稳定梯度；对 flow / MeanFlow 类策略是可复用的训练配方。
    • 非对称表示对齐：只对下游侧（action）加约束、上游侧 stop-gradient，可以避免两个表示空间互相拉扯；cosine 而非 MSE 则避免把”语义一致”写成”逐元素相等”。
    • “role-matched supervision” 的提问方式：先问每个中间表示在最终任务里承担什么职责，再决定监督信号，这比”给每个模块都加一个辅助 loss”更有结构。
  • 待跟进：
    • 用固定 backbone、固定 epoch、只改采样步数的对照，重算 190 vs 1,600 GPU-hours，把”一步生成”的净收益从”更小模型 + 更短训练”里剥离出来。
    • 补齐 occupancy 提取器的输入模态与训练数据，确认”仅相机输入”是否成立；若不成立，需要重做 zero-shot 的部署假设。
    • 对 VARA 做四组对照（对齐到 CLS、对齐到 world token、双向、MSE），并用线性探针检查 Ha​ 是否编码了前车距离 / TTC / 车道几何，判断它到底传递了什么语义。
    • 统计 HUGSIM Easy 与 Extreme 两档的失败类型，验证”混合先验覆盖不足”这一猜测，或找出 TrajMF 在极端场景退步的真实原因。
